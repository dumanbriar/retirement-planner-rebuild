# Horizon Retirement Planner — Comprehensive Audit (July 2026)

**Scope**: full codebase — projection engine (`backend/app/engine/`), API
(`backend/app/main.py`), React dashboard (`frontend/src/`), Excel export, and
the deployment pipeline. Three questions were asked of every number:

1. Is the math correct against the primary statutory source?
2. Is it displayed correctly (and honestly labeled) in the UI?
3. Can it be tied out from the exported Excel audit workbook?

**Method**: line-by-line review of the engine and every results component;
independent hand-checks of tax formulas against Rev. Proc. 2025-32, IRC §86 /
§1(h) / §1411, SSA claiming formulas, SECURE 2.0, CMS 2026 premiums, and Rev.
Proc. 2025-25; plus scripted numeric verification of the engine's internal
accounting identities (account roll-forward, retirement cash-flow foot,
lifetime-tax aggregation) on multiple scenarios. 60 backend tests pass
(55 pre-existing + 5 regression tests added by this audit).

---

## Verdict

The tool is well built for advisor use: deterministic, source-cited, and
assumption-forward. The statutory parameters were verified correct against
primary sources (see inventory below). The audit found **five real math /
correctness defects** (all fixed in this change), **six display / tie-out gaps**
(fixed), and a set of modeling simplifications that were correct but
insufficiently disclosed (now disclosed in the Assumptions strip and workbook).
Two deployment-hygiene issues need an operational decision (see last section).

## Findings fixed in this change

### Math defects (engine)

**M1 — Lifetime taxes double-counted penalties.** `metrics.lifetime_taxes`
summed `row.total_tax + row.penalties`, but retirement rows already include
penalties inside `total_tax`. In a pre-59½ retiree scenario this overstated
lifetime taxes by $83,971. Affected the Lifetime-taxes metric card, the Excel
Summary, and the lifetime-tax columns of every strategy comparison (rankings
were unaffected — the optimizers rank on ending after-tax wealth).
*Fixed: sum `total_tax` only; accumulation rows now populate `penalties` consistently.*

**M2 — Early-withdrawal penalties were recognized as tax but never funded.**
The retirement withdrawal target excluded penalties incurred *during* the
waterfall (10% pre-59½, 20% HSA non-medical), so in gap years the penalty
dollars never left any account: assets were overstated and the cash-flow
identity missed by exactly the penalty (−$10,577 in the verification year).
*Fixed: penalties join the tax/ACA fixed-point iteration and are withdrawn like
taxes. Identity residual is now < $2 in all tested years.*

**M3 — Home-purchase raids during accumulation were taxed too lightly.**
Funding a future-home down payment by selling appreciated taxable shares (or
raiding tax-deferred/HSA) realized gains and ordinary income **tax-free** —
only the 10% penalty was charged. In the verification scenario a $300k down
payment realized $85k of gains with $0 tax. *Fixed: the raid now runs before
the year's tax computation; realized gains and raided pre-tax dollars flow into
that year's tax (full engine when salaried; flat rate + the documented 15% gains
rate otherwise). `realized_gains` is now reported on accumulation rows and in
the workbook.*

**M4 — IRMAA two-year lookback ignored modeled wage MAGI.** Accumulation years
always stored the 1.5×-spending fallback estimate even when salaries produced a
real computed MAGI ($175k estimate vs $307k actual in the sample household),
understating IRMAA surcharges in the first two Medicare years. *Fixed:
priority is now user-entered pre-retirement MAGI → modeled wage MAGI →
1.5×-spending estimate, and the priority is disclosed in the Assumptions.*

**M5 — "Social Security cut 23% in 2034" scenario cut benefits from day one.**
The sensitivity scenario scaled the PIA, which also reduced benefits received
*before* 2034 — wrong for anyone claiming earlier. *Fixed: the engine now takes
an `ss_cut=(year, factor)` hook; the scenario cuts only benefits paid in 2034+.*

### Display / tie-out gaps (UI ⇄ Excel)

**T1 — "Wd HSA" meant different things on screen and in the workbook.** The
dashboard column showed only non-medical HSA withdrawals; the Excel column
showed total HSA withdrawals including tax-free medical draws ($0 vs $8,038 in
the same year of the sample plan). *Fixed: the workbook now has two columns —
"W/D HSA (medical)" (netted inside Healthcare) and "W/D HSA (non-medical)"
(matches the dashboard) — with an explanatory note, and the dashboard/chart
tooltips state exactly which figure they show.*

**T2 — Accumulation-year tax detail shown in the UI wasn't in the workbook.**
The year table displays AGI, total tax and effective rate for working years
(when salaries are modeled), but the Accumulation sheet had only a single tax
column — the wage-tax math couldn't be tied out. *Fixed: Accumulation sheet now
includes Realized gains, AGI, Taxable income, Federal tax, State tax,
Penalties, Effective rate, and Surplus reinvested.*

**T3 — "Every input" was not in the Assumptions sheet.** State tax rate,
dividend yield, heir rate, pre-retirement tax rate, contributions-grow flag,
conversion strategy/custom amount, both optimizer toggles, the three healthcare
cost estimates, and pre-retirement MAGI were missing. *Fixed: all assumption
fields are now printed as explicit input rows.*

**T4 — Today's-$ figures were not directly reproducible.** The dashboard's
Today's-$ toggle deflates every cash flow, but the workbook carried only
nominal cash flows. *Fixed: both year sheets now include a "Deflator (÷ nominal
→ today's $)" column using the identical deflator.*

**T5 — Dashboard subtitle claimed "All figures in nominal dollars" in nominal
mode**, while metric cards and all four strategy tables are always in today's
dollars. *Fixed: subtitle now states which elements follow the toggle.*

**T6 — Stale/incomplete captions.** The Account Detail footnote said reinvested
amounts appear only "in retirement years" (they also carry accumulation inflows
and tax savings); the "Contrib." tooltip referenced a surplus column that didn't
exist (a "Surplus reinv." column has been added to the year table); the
pre-retirement-tax-rate help still said "wages themselves are not modeled";
the tax-chart tooltip omitted penalties from its breakdown; a `types.ts` comment
described the contribution split as per-person. *All fixed.*

### Disclosure gaps (now noted in the Assumptions strip + workbook)

These behaviors were **correct code** but were not visible to an advisor:

- **State income tax** is a single flat rate on federal taxable income in all
  years (no brackets, no SS/retirement-income exclusions).
- **Living costs before household retirement** are assumed paid from wages —
  including years where one spouse has already retired.
- **SS survivor/spousal simplifications**: survivor step-up starts at the
  survivor's own claim age (no widow(er)-at-60 claiming, no RIB-LIM cap); a
  spouse who dies before claiming leaves no modeled survivor benefit
  (conservative); spousal top-up assumes deemed filing.
- **IRMAA lookback MAGI source** (user input → wage MAGI → 1.5× spending).
- **Not-modeled inventory**: FICA, HSA contribution limits (entries are not
  checked against §223 caps), SECURE 2.0 mandatory-Roth catch-up for high
  earners (effective 2026), Roth 5-year clocks, IRA pro-rata rule, itemized
  deductions, QCDs, estate/gift tax.
- Home-purchase note updated to state that raid withdrawals are now taxed.

## Remaining simplifications (documented, acceptable, not changed)

- Annual granularity: end-of-year ages, whole-year 59½→60, whole-year claiming
  ages (a person with a fractional FRA claims in whole years). Disclosed.
- IRS indexes with chained CPI rounded to $25/$50 steps; the engine indexes at
  the plan inflation assumption. Disclosed in the workbook and constants file.
- One inflation assumption serves as CPI, SS COLA, and wage growth. Disclosed.
- The marginal-rate column shows the first-bracket rate when taxable income is
  zero (cosmetic).
- `BASE_YEAR = 2026` is compile-time: every plan starts in calendar 2026. Fine
  today; **must be bumped during the annual constants refresh** (the freshness
  panel tracks the constants but not the base year itself — added to the
  maintenance checklist below).

## Freshness status (as of 2026-07-02)

No constant group is past due: brackets/deductions/LTCG due 2026-10-01 (Rev.
Proc.), Medicare/IRMAA and contribution limits due 2026-11-01, FPL due
2027-01-15, ACA percentages re-verified 2026-06-21. The in-app stale-review
panel and `/api/constants/freshness` govern this correctly.

**Annual maintenance checklist** (each October–January): update
`constants.py` values + `CONSTANT_METADATA`, bump `BASE_YEAR`, re-run tests
(several hand-computed expectations are 2026-specific and will fail loudly —
that is intentional).

## Deployment & the two live versions

- This repo's CI (`.github/workflows/deploy.yml`) deploys the Railway engine +
  Vercel frontend on pushes to `main` (does not exist), `claude/laughing-pasteur-8uq412`
  (current deploy source), and `claude/ecstatic-hypatia-msb2t4` (branch deleted).
  **The fixes in this audit will not reach the live app until this branch is
  merged into / fast-forwarded to `claude/laughing-pasteur-8uq412`, or the
  workflow's branch list is updated.** Recommend consolidating on a real `main`.
- The pre-rebuild app ("v1", the version deployed before the legacy/estate
  planning after-tax valuation existed) is **not in this repository** — only
  this rebuild is. Both versions being reachable is a real advisor-facing risk:
  the two engines will show different numbers for the same client. Recommend
  taking the v1 deployment down or adding a prominent deprecation banner that
  links to the current app (plans can be moved via the JSON export/import
  added in `9e890f3`).
- Live URLs could not be probed from this audit environment (network policy),
  so which commit each deployment currently serves was not verified directly.
